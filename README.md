# Imbue

**あなたの判断と流儀を、エージェントに吹き込む。**

Imbueは、AIコーディングエージェントとの日々の仕事を学習データに変え、ファインチューニングを通じて、あなたに合うエージェントを育てるためのCLIプロダクトです。

名前の *imbue* は、英語で「性質を吹き込む」「染み込ませる」という意味。会話の中で伝えた意図や修正を、次の仕事で使える判断として定着させることを目指します。

> ローカルCLIの初期実装があります。Codexの作業ログ収集・保存・確認と、Codex上のLunaによるバッチ整形に対応しています。追加学習と学習済みモデルの実行は後続段階です。

## ローカルで使う

Go・sqlc・Docker Desktopを用意して、次を実行します。

```sh
make build
./bin/imbue init
./bin/imbue start
./bin/imbue
```

`imbue`（または `imbue ui`）で、色鮮やかなドットの脳を描くターミナルUIが開きます。`1`〜`4`でホーム・会話・判断事例・処理履歴を切り替え、`↑↓`と`Enter`で詳細を閲覧できます。判断事例の詳細では`g`で根拠を表示します。`v`はLuna専用アカウントの確認、未起動時の`s`はサービス起動、`q`はUIを閉じます。収集サービスはUIを閉じても動き続けます。既存の `imbue status` などのCLIもそのまま使えます。

既定では、初期化後にCodexで開始・再開したすべての作業ディレクトリを自動検出します。会話と判断事例には元の作業ディレクトリを保持します。`imbue scope repository PATH`で一つのディレクトリだけに限定でき、`imbue scope all`で再び全体へ戻せます。範囲変更後はImbueを再起動します。

初期状態では収集のみを行います。Lunaの確認・有効化、保存したEvidenceや判断事例の閲覧、対応Codexバージョン、取得できる情報の範囲は[ローカル実装と動作確認](.docs/16-local-implementation.md)を参照してください。

## なぜ作るのか

「この変更なら、そこまで直さなくていい」「まず既存の実装を調べてほしい」「ここは確認せず進めていい」。

エージェントとの仕事では、コードの正しさだけでなく、変更範囲、調査の深さ、品質の基準、任せる範囲を何度も伝えています。その場で直っても、次の仕事で同じ説明が必要になることがあります。

Imbueは、こうしたやり取りに現れる判断を経験として蓄積し、エージェントが学べる形に整えます。

## 目指す体験

1. **普段どおりに働く** — エージェントへの依頼、修正、承認、コード差分、テスト結果を収集します。
2. **経験を学習データにする** — どの状況で何を選び、どう修正したかを、元の記録に紐づく学習事例として整理します。
3. **内容を確かめ、直す** — 抽出された事例を自然言語で編集・分割・削除し、学習に使うデータを管理します。
4. **モデルを育てる** — ユーザーが明示的に学習を開始し、判断や流儀をモデルに定着させます。
5. **未知の仕事で確かめる** — 個人への適応と一般能力の維持を評価し、条件を満たしたモデルを利用します。履歴を残し、以前の版へ戻せるようにします。

## 仕組み

```text
日々の仕事
会話・ツール操作・コード差分・テスト・後日の修正
    ↓
根拠となる記録
    ↓
状況・選択・修正・結果を整理した学習事例
    ↓
バージョン管理されたデータセット
    ↓
ファインチューニング → 評価 → モデルの切り替え
```

元の記録、そこから抽出した解釈、学習用データを分けて保存します。コードやテストも判断の根拠として保持し、各事例を元の仕事まで辿れるようにします。

中心となる資産はデータセットです。モデルや学習方式が変わっても経験を再利用できるようにし、Memory・Skill・評価データへの変換も設計に含めています。

## 最初に検証すること

まずは一人、一つのリポジトリ、一つの判断領域に絞ります。初期の対象は、既存実装に対して「どこまで変更するか」という判断です。

同じ基盤モデルで、次の三条件を比較します。

- 追加学習をしていないモデル
- 過去の経験をSkill・Contextとして渡したモデル
- 同じ経験でファインチューニングしたモデル

少量のデータとLoRAによって個人の判断が身につくかは、これから検証する仮説です。未学習の仕事での改善、一般能力の低下、対象外の仕事への好みの誤適用、費用・遅延を確認します。

## 初期の技術構成（予定）

| 領域 | 構成 |
| --- | --- |
| アプリケーション | Go製のCLI・API・Worker・Gateway |
| データベース | PostgreSQL、pgx、sqlc |
| ファイル保存 | ローカルファイル |
| ジョブ管理 | PostgreSQLのジョブテーブル |
| エージェント実行・学習事例の整理 | Codex |
| ファインチューニング・推論 | Fireworks |

まずは一人のPCで動く構成から始めます。AI実行・学習には外部サービスを利用します。クラウド配備、サービス認証、課金、チーム共有は後段の対象です。
