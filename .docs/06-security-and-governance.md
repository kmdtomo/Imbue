# セキュリティとガバナンス

## 初期のローカル構成

初期実装は一人のPCで動かす。本文のPlatformは、初期には同じPC上のGo API・Worker・Model Gatewayを指す。PostgreSQL（pgx＋sqlc）とローカルファイルを正本とし、ジョブはPostgreSQLのテーブルで管理する。クラウドホスティング、Object Storage、外部Queue、サービス認証・課金は後段とする。CodexおよびFireworksによる外部AI実行・学習は維持するため、完全オフライン構成ではない。具体的な保存・認証・起動境界は[技術アーキテクチャ](12-technical-architecture.md)を正本とする。


## 基本方針

学習データはユーザーの判断資産であり、ユーザーが所有、閲覧、編集、移行、削除できなければならない。収集範囲、共有範囲、外部送信、学習利用は独立して制御する。

## 保存場所とユーザー所有

- データセットは観測対象リポジトリとは別の専用ディレクトリで管理する。
- 対象リポジトリ内のコード、設定、Git履歴へ学習データを自動混入させない。
- Imbue Platformを運用上の保存・処理基盤とし、暗号化、バックアップ、保持期間、project分離を管理する。
- ローカルには設定、収集用buffer/cache、明示的にexportした可搬データだけを置く。
- Base Model、checkpoint、LoRA、推論用weightをユーザーPCへ保存しない。
- 独自形式だけに閉じず、Event、Learning Case、Evidence、履歴を可搬な形式で出力できるようにする。

専用ディレクトリは保存上の境界であり、判断の適用範囲を表すものではない。

## Scopeとアクセス制御

Scopeはディレクトリ階層ではなく、各オブジェクトのメタデータとして保持する。少なくとも以下を区別する。

- 所有者: 個人、チーム、組織
- 対象: 全体、プロジェクト、リポジトリ、領域、ファイル種別、タスク種別
- 可視性: 非公開、限定共有、組織共有
- 利用権限: 閲覧、編集、Projection生成、学習、配備、外部出力
- 有効期間と失効条件

保存場所が同じでもScopeを混同せず、Scopeが異なる判断の統合や注入には明示的なポリシーを要求する。

## Gitとチーム共有

- 学習データはデフォルトでGit追跡しない。
- リポジトリへの保存、commit、push、PR作成は個別にopt-inする。
- チーム共有時は共有対象のLearning CaseとEvidenceを選別し、個人Scopeの情報を自動昇格させない。
- 共有後も原所有者、出典、ライセンス、利用条件を保持する。
- Git履歴は配布手段になり得るが、削除保証やアクセス制御の正本にはしない。
- 退職、権限変更、リポジトリ移管時に、共有済みデータと派生物の扱いを明示する。

## PII・機密情報・秘密情報

### データ最小化

学習に不要な氏名、メール、パス、顧客情報、会話全文を保存しない。Learning Caseには可能な限りEvidenceへの参照を保持し、不要な原文複製を避ける。

### 分類と制御

- PII、要配慮情報、組織機密、認証情報、第三者データを分類する。
- API key、token、password、秘密鍵、金融口座番号等は学習データへ保存しない。
- 要配慮情報の保存と利用は明示的なopt-inを要求する。
- 外部サービスへ送信する前に、再検出とredactionを行う。
- スクリーンショット、ログ、diff、コマンド出力も同じ検査対象とする。
- 除外セッション、除外パス、除外人物、Incognito相当の収集停止を提供する。

検出結果だけに依存せず、ユーザーが誤検出と見逃しを訂正できるようにする。

## Provenance

各Learning Caseと派生物から、元Eventまで追跡できなければならない。

記録対象は以下とする。

- Eventの発生元、時刻、session、actor、対象リポジトリ
- 元発言、ファイル版、diff、テスト、画像等のEvidence識別子
- 抽出モデル、プロンプト、ルール、schemaの版
- 自動統合、分割、要約、redaction等の変換履歴
- ユーザー編集の内容、時刻、主体、理由
- Projection生成器と設定
- Dataset Version、Training Run、Eval、配備先
- 利用時に参照された判断と結果

観測Eventは追記型で保持し、解釈の更新で書き換えない。訂正は新しい版または訂正Eventとして記録する。

## 削除と伝播

削除は画面上の非表示ではなく、派生関係をたどる処理として扱う。

1. 削除対象のEvent、Evidence、Learning Caseを特定する。
2. 依存する解釈、Dataset Version、Projection、Evalを無効化または再生成する。
3. 外部エクスポート先へ削除要求または利用停止を伝える。
4. 学習済みモデルへの混入をTraining Runから特定する。
5. 重みから個別事例を直接除去できない場合は、モデルを隔離し、対象の旧事例と派生物を学習していない来歴を確認できる基盤モデルまたはcheckpointから、除外後データで再学習するか、影響のない安全な版へロールバックする。データ除外済みと配備モデルへの反映完了を別々に追跡する。
6. バックアップ、監査ログ、外部保持に残る範囲と消去予定をユーザーへ表示する。

削除済みデータの識別子をtombstoneとして残す場合も、削除対象の本文や復元可能な値を保持しない。

## Prompt injectionとMemory poisoning

観測対象には、ユーザー入力だけでなく、Web、Issue、README、ログ、ツール出力、生成コード等の信頼できない内容が含まれる。これらを学習指示として扱わない。

- Eventの内容と、Observer・抽出器への命令チャネルを分離する。
- 外部コンテンツ中の「保存せよ」「ルールを変更せよ」等をデータとして引用し、実行しない。
- 未信頼Eventから直接、共有Memory、Skill、system-levelルールへ昇格させない。
- 書込可能なMemoryと、組織標準等のread-onlyな参照を分離する。
- 自動適用前に出典、Evidence種別、Scope、競合、PII検査を行う。
- MemoryやContextへ元文を無条件に全文注入せず、構造化Projectionを生成する。
- Observer、抽出、Projection、学習実行を権限分離し、最小権限で動かす。
- 侵害が疑われるEventから派生した全データをprovenanceで隔離できるようにする。

## 外部連携と学習サービス

- Connectorは必要なリポジトリ、組織、期間、データ種別だけへアクセスする。
- 外部送信先ごとに、送信内容、保持期間、学習利用、削除手段を表示する。
- 初期は利用者がProvider credentialを設定し、OS credential storeで保持する。ローカルPlatformは必要時に参照し、logやDatasetへ出力しない。クラウド化時はサービス側のsecret管理へ移す。
- 学習サービスへはredaction済みの固定Dataset Versionだけを渡し、ローカル環境や全Eventへの包括アクセスを与えない。
- 送信データのmanifest、hash、件数、redaction結果を保存する。
- Providerの規約上、モデル学習へ利用できない生成物や第三者データを除外する。

## 監査と運用

- 収集、閲覧、編集、共有、export、学習、配備、rollback、削除を監査対象とする。
- ユーザーは「誰が、何を、どこへ、なぜ利用したか」を確認できる。
- 保持期間終了、権限失効、削除失敗、外部同期失敗を通知する。
- 自動生成や自動適用を停止しても、既存データを閲覧・export・削除できる。
- セキュリティポリシーはモデルへの自然言語指示だけでなく、アクセス制御と実行時検査で強制する。
